How SPEADE works

The seven steps

  1. Type your module code (e.g. MG2001) in the box top left. Everything you add and process belongs to that module - each module keeps its own folders, and the sidebar groups documents per module (click a module's name to open or hide its list).
  2. Add PDFs… - they appear under your module. Aim for about 50 at a time - a comfortable amount to review; do several batches if a module has more.
  3. Process PDFs - processes YOUR module's waiting PDFs only. The app reads scans (OCR) and adds accessibility tags. Already-processed files are skipped automatically, so splitting a big pile into batches costs nothing. Newly processed documents appear at the top; approved and rejected ones tidy themselves away under Done.
  4. Review - click a document. The left side lists every heading, paragraph, list, and image; the right side shows the pages with a box around each tagged part. Click either side to highlight the other.
  5. Title & language - set what a screen reader should announce, then save.
  6. Decide - Approve (moves to the approved folder, done) or Reject (moves to rejected).
  7. Fix and return - repair rejected PDFs in Adobe Acrobat Pro, save over the same file, come back and Approve. Not approved = not done.

What to check when reviewing

  • Do the headings in the list match the document's real headings?
  • Does the top-to-bottom order match sensible reading order?
  • Are lists and tables tagged as lists and tables?
  • Does every meaningful image say Image - and have a description? ("needs description" means you write one, below the pages.)
  • Is any visible content missing a box entirely? No box = not tagged.

Fixing tags without leaving the app

  • One tag - click it (tree or page box): change its type, write an image description, mark it decorative, remove a wrapper, or move it earlier/later in the reading order.
  • All images in one pass - Alt Text (top right) opens a stepper like Acrobat's Set Alternate Text: it walks image by image, you write a description (or tick Decorative figure), and the arrows save as they move. It normally slides itself out of the way of each image; drag its blue title bar to park it wherever you prefer, and it stays there.
  • Tag something new - pick a type in Drag on the page to tag as (above the pages), then drag a rectangle over it. Content with no tag at all, or some of a tag's lines (the fix for a heading swallowed into a paragraph), is tagged straight away - no button to press. This is also how you bring back anything marked decorative.
  • Many tags at once - drag across two or more existing tags and a bar appears, because there is a real choice: merge them into one tag (the fix for over-fragmented text), change all, or mark all decorative.
  • Undo - Undo last change steps back one edit at a time; Undo all edits starts over from the original. Every edit is recorded in History; the accessibility check runs when you press Run Auto Check (or automatically, if you switch that on in Settings) - and always when you Approve or Reject.
  • Still Acrobat's job: selecting part of a single line and table header cells.

Common questions

Why are Add PDFs and Process PDFs greyed out?
Type your module code first (the box top left). Adding and processing always happen for one module at a time.
Where did my approved document go?
Into its module's Done section in the sidebar (click to open), and on disk into that module's approved folder. Nothing is deleted.
Why did it skip some files when I pressed Process?
They were already processed and haven't changed. Replace the file in the input folder with a new version to process it again.
What does "Edited since processing" mean?
The file changed after the app made it - normally because you fixed it in Acrobat. That's expected; approving records the file as it is now.
A document says it is password-protected or damaged.
The app never guesses passwords and can't repair broken files. Ask the document's owner for a usable copy and add it again.
What is the "automatic check"?
veraPDF, the official PDF/UA accessibility validator. Its verdict is advice - your Approve/Reject is the decision, and it is recorded.
Why does it say "not checked since your last change"?
The check takes a few seconds, so it does not run after every edit - that would make writing several descriptions painfully slow. Press Run Auto Check whenever you want the current result, and note that Approve/Reject always runs it, so nothing can ship unchecked. You can switch it back to running after every change in Settings.
How do I clear finished documents out of the list?
Hover a document (or a module heading) and click the ×. That only tidies the list - every file stays exactly where it is, and Put all back at the bottom of the list restores them.
Who writes the image descriptions?
You do - select the image and type it below the pages (or in Acrobat). Descriptions are never machine-written. That's deliberate: quality needs a human.
Where do finished documents go?
outbox\approved - share the PDF only; the app's record files stay behind.

The three rules

  1. Originals are sacred - corrections happen on the draft, never the source file.
  2. Nothing ships without a human - only your Approve makes it accessible.
  3. When unsure, reject and ask - the queue can wait; students relying on the document can't.

More detail: the full user guide and the Acrobat correction guide are in the project's docs folder.
